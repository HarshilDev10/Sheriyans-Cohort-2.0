Best SEO Practises and Core Web Vitals. 

1.CLS [ Cummulative Layout Shift ]

Cumulative Layout Shift (CLS) is a web performance metric that measures how much the visible content on a webpage unexpectedly moves around while the page is loading or during its lifetime.

It is one of Google's Core Web Vitals because unexpected layout shifts create a poor user experience.

Example

Imagine you're reading a news article:

- The page loads, and you start reading.
- Suddenly, an advertisement loads above the paragraph.
- The entire page shifts downward.
- You accidentally click the wrong link because the button moved.

This unexpected movement contributes to the page's CLS score.

Common causes of high CLS
- Images without specified width and height
- Ads or embedded content loading after the page has rendered
- Dynamically inserted banners or notifications
- Web fonts causing text to resize (Flash of Unstyled/Text Swap)
- Content injected above existing content
- Animations that change layout (using top, left, height, etc., instead of transform)

How to reduce CLS

Here are some best practices:

✅ Always specify image dimensions:

<img src="photo.jpg" width="800" height="600" alt="">
✅ Reserve space for ads, embeds, and iframes.
✅ Avoid inserting new content above existing content unless triggered by user interaction.
✅ Use font-display appropriately and preload important fonts.
✅ Animate with transform and opacity instead of properties that trigger layout changes.
✅ Reserve space for dynamically loaded components using placeholders or skeleton loaders.

2.FID [ First Input Delay ]

FID (First Input Delay) is a web performance metric that measures how long it takes for a webpage to respond to the user's first interaction.

It was one of Google's Core Web Vitals, but it has now been replaced by INP (Interaction to Next Paint) because INP provides a more complete measure of responsiveness.

What FID measures

FID is the time between:

- The user first interacts with the page (such as clicking a button, tapping a link, or pressing a key), and
- The browser is actually able to begin processing that event.

It does not measure how long the action takes to complete—only the delay before processing starts.

Example

Suppose a webpage is loading JavaScript.

0 ms      Page loads

500 ms    User clicks "Login"

500–650 ms    Browser is busy executing JavaScript

650 ms    Browser starts processing the click

FID = 150 ms

GOOD FID Score
|        FID | Rating               |
| ---------: | -------------------- |
|   ≤ 100 ms | ✅ Good               |
| 100–300 ms | ⚠️ Needs Improvement |
|   > 300 ms | ❌ Poor               |


What causes high FID?

The most common cause is heavy JavaScript blocking the browser's main thread.

Examples include:

Large JavaScript bundles
Long-running JavaScript tasks
Heavy third-party scripts
Complex page initialization
Excessive synchronous code

When the main thread is busy, the browser can't respond to user input immediately.

How to improve FID

Some common optimization techniques are:

Split large JavaScript files into smaller chunks.
Remove unused JavaScript.
Defer or asynchronously load non-critical scripts.
Break long tasks into smaller tasks (under ~50 ms when possible).
Use Web Workers for CPU-intensive work.
Reduce the impact of third-party scripts.

A Lighthouse Report is a performance and quality audit generated by Google Lighthouse, an open-source tool that analyzes web pages and provides recommendations to improve their quality.

It helps developers measure how well a website performs and identifies issues related to performance, accessibility, SEO, and more.

What Lighthouse analyzes

A Lighthouse report evaluates a website in five main categories:

Category	What it checks
🚀 Performance	Loading speed, responsiveness, Core Web Vitals, resource optimization
♿ Accessibility	Usability for people with disabilities (screen readers, color contrast, alt text, etc.)
✅ Best Practices	Security, modern web standards, HTTPS, JavaScript issues
🔍 SEO	Search engine optimization basics like meta tags, crawlability, structured content
📱 Progressive Web App (PWA) (optional)	Whether the site behaves like an installable app (older audits or when applicable)
